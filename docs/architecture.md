# Архитектура AI Workspace Manager

Проект объединяет исходный Claude Code Local Model Switcher и переносимые скрипты `codex-multi-account` (исходный коммит `aa89d5e`, «Add portable Codex multi-account setup»). Git-истории обоих исходных репозиториев сохраняются в объединённом репозитории. Каталоги аккаунтов не являются частью исходников.

## Направление зависимостей

```text
start.ps1 → manager.ps1 → выбранный агент в отдельном процессе
                               ↓
                  agents/claude или agents/codex
                               ↓
                            shared
```

`shared` не зависит от реализации агентов. Здесь находятся JSON/JSONC, имена и пути профилей, Windows argv, временное окружение и запуск VS Code. Модули не импортируют друг друга. Общий менеджер знает только точки входа и поддерживаемые параметры, а авторизацию и готовность к запуску проверяет выбранный модуль.

## Профили и авторизация

У профиля есть инструмент, имя и собственные каталоги состояния. Одинаковое имя, например `work`, у Claude и Codex относится к разным каталогам. Единый реестр аккаунтов не требуется: Claude использует `switcher.json`, Codex — `profile.json` в уже существующих каталогах. `shared/profiles.ps1` определяет корни и проверяет допустимость имён и путей.

Claude управляет `CLAUDE_CONFIG_DIR`, состоянием своего расширения и проверкой `claude auth status`. Codex управляет `CODEX_HOME`, device login и чтением локального состояния аккаунта. Наличие читаемой структуры `auth.json` не доказывает действительность токена на сервере; вход и реальная работа остаются проверкой установленного клиента. Повреждённый `auth.json` не считается успешным входом.

Настройки моделей и локальный backend относятся к модулю Claude. Это отдельная настройка от входа в claude.ai. Мост `openai_bridge.py` переводит протокол для Claude и не занимается входом в ChatGPT/Codex.

## Совместимость

- Прежний Claude-профиль остаётся в `ClaudeLocalSwitcher/account-b`. Параметр `StateRoot` сохраняет назначение.
- Именованные Claude-профили задаются общим менеджером через отдельный `StateRoot`.
- Единый менеджер передаёт параметры выбранному модулю. Прямой CLI и Python-адаптер Claude находятся в `agents/claude/`; устаревшие корневые точки входа удалены.
- Codex сохраняет `CodexAccounts`, `CODEX_MULTI_ACCOUNT_ROOT`, версию 1 `profile.json`, device login и общий каталог расширений.
- Общий запуск VS Code проверяет принятие команды CLI. Ошибка запуска не выдаётся за успех.
- Основные `.claude`, `.codex` и пользовательские данные обычного VS Code не принимаются как каталоги состояния профилей.
- Все смены окружения выполняются с восстановлением в `finally`. Наследованная маршрутизация второго агента и API-ключи удаляются из запускаемого процесса.

## Развитие

Новую агентскую функцию добавляйте в её модуль. Общую функцию выносите в `shared` при наличии реальных потребителей; общие функции не должны хранить токены или интерпретировать специфичные настройки агента. При добавлении третьего инструмента обновляйте диспетчер и тесты его поддерживаемых действий, сохраняя собственную авторизацию и каталоги состояния.

При изменении путей проверяйте общий менеджер и прямые точки входа модулей. Тестовые аккаунты и исполняемые файлы остаются синтетическими; проверка реальных версий расширений и моделей проводится отдельно от регрессионного набора.
